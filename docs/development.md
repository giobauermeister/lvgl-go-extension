# Development

## Build and test

Use Node.js 22 or newer and npm:

```sh
npm ci
npm test
npm run package
```

`npm test` compiles TypeScript and runs the Node test suite. Tests use temporary directories and local HTTP/HTTPS servers; certificate fixtures require OpenSSL.

In VS Code, press F5 to launch an Extension Development Host, then open an LVGL Pro project there. Building UI previews also requires the Emscripten SDK and CMake listed in the README.

The runtime prefers SDL’s `opengles2` renderer (WebGL) to present the LVGL framebuffer. LVGL still draws the UI in software, but WebGL avoids an additional full-frame CPU alpha blend during presentation. SDL falls back to its normal renderer selection if WebGL is unavailable. Animated, high-resolution projects can still spend substantial time generating and drawing frames on the browser’s main thread.

## GitHub Actions

The **Build packages** workflow installs dependencies from `package-lock.json` and runs the tests:

- Pull requests into `main` or `master` run tests before merging.
- Pushes to `main` or `master`, including merges, also build both packages.
- Version tags beginning with `v` build both packages and publish a GitHub Release.
- Manual runs from the Actions tab build both packages without publishing a release.

Other branch pushes do not trigger the workflow.

Open a successful run under **Actions → Build packages → Artifacts** to download:

- `lvgl-go-VERSION.vsix` to install the extension.
- `lvgl-go-pwa.zip` to deploy the PWA to Netlify or another static host.

The files are uploaded directly, without another ZIP wrapper, and retained for 30 days. Tagged releases provide permanent downloads on the repository's **Releases** page. No additional repository secrets are required.

## Publish a version

Update `version` in `package.json` and `package-lock.json`, then merge that change into `main` or `master`. Tag the merged commit with the same version prefixed by `v`:

```sh
git tag v1.0.0
git push origin v1.0.0
```

The tag must match the package version and point to a commit already merged into `main` or `master`. After tests and packaging succeed, the workflow uploads the tested VSIX and PWA ZIP to a GitHub Release. Versions containing a prerelease suffix, such as `1.1.0-beta.1`, are marked as prereleases.

A new release stays in draft until both files are attached. Rerunning a tag build completes missing uploads while preserving existing release files.

## Build output

| Path | Purpose |
| --- | --- |
| `dist/` | Compiled extension JavaScript and source maps for debugging and tests. |
| `artifacts/lvgl-go-VERSION.vsix` | Extension installer generated by `npm run package`. |
| `artifacts/extension-readme.md` | Formatted description embedded in the extension installer. |
| `artifacts/pwa/` | Static site generated by `npm run package:pwa`. |
| `artifacts/lvgl-go-pwa.zip` | ZIP of the static PWA for deployment. |
| `.lvgl-go/` | Local preview caches created by the development harness. |

These directories are generated and ignored by Git. Commit the source files, `package-lock.json`, shared debug tasks and icon assets. Distribute installers and deployment ZIPs as release assets.

## Public repository contents

The repository, VSIX and PWA package contain LVGL Go's integration code and UI assets. They do not bundle LVGL Pro Editor sources, `lv_xml` sources, LVGL SDK headers or libraries, or compiled project previews. The extension locates matching LVGL resources on the user's computer when building a preview. Its C runtime contains calls to LVGL APIs and build configuration references to those resources.

The PWA is a static launcher and needs no Netlify account credentials. Its default public address is `https://go.bauertronix.com.br/app/`; Netlify instructions in the hosting guide use placeholder addresses. Local Netlify state, environment files, private keys, preview caches and build output are ignored by Git.

## Documentation

Edit `README.md` for the shared introduction and GitHub documentation links. Edit `docs/` for the detailed user guides. Run `npm run docs` to generate the extension description; `npm run package` also runs this step.

The extension description uses the README introduction before its **Documentation** section, followed by expandable usage guides. Contributor instructions remain in the GitHub README and this guide. Generation never overwrites `README.md`.

README images are stored in the repository. The generated extension description resolves them to public HTTPS URLs on the repository's `main` branch so they also work in extension listings.

## Preview harness

After `npm run compile`, run `node scripts/preview-project.js PROJECT --local` to build a project and preview it on the same computer. Omit `--local` to test the public tunnel flow.

## Icons

Edit `media/icon.svg`, then run `npm run icons` to regenerate the extension and PWA icons and the iPhone/iPad startup images. Screen sizes are listed in `scripts/startup-images.js`. This command requires Inkscape; `INKSCAPE` can select its executable.

For PWA deployment, see [PWA hosting](hosting.md).
